# Mesij TypeScript REST API MVP

This directory contains a portable, framework-free, **standalone** REST API for
Mesij-style event exchange. The same Fetch API handler runs on **Node.js 24+**
with built-in `node:sqlite` and on **Cloudflare Workers** with D1. Its database is
owned by this package and must not be shared with the Go Mesij CLI.

The MVP implements only:

- `GET /healthz` (public liveness)
- `GET /v1/status`
- `POST /v1/events`
- `GET /v1/events` (bounded snapshot pagination and filters)
- program-generated, project-scoped API tokens
- append-only events and idempotency facts

It deliberately does **not** implement Mesij's complete active-work projection,
conflict `check`, agent aliases, recipient resolution, mentions, inbox, TUI, or
streaming tail. Lifecycle event names are stored as immutable facts only. Do not
treat this standalone MVP as a replacement for the full Go Mesij operations or
point it at a Go Mesij database.

## Install and verify

From `api/`:

```sh
npm install
npm test
npm run typecheck
```

There are no runtime dependencies. TypeScript, Wrangler, and Node type
definitions are development dependencies.

## Node.js quick start

Build, initialize a dedicated API database, and create a token. `db init` writes
and verifies a product metadata marker; it refuses a non-empty unmarked database,
including a detected Go Mesij database. The plaintext token is printed exactly
once by `token create`; only its SHA-256 hash is stored.

```sh
npm run build
node dist/src/cli.js db init --db ./.mesij-api/mesij-api.sqlite3 --project demo
node dist/src/cli.js token create --db ./.mesij-api/mesij-api.sqlite3 --project demo --label local
# Save the printed mesij_v1... value securely.
node dist/src/cli.js serve --db ./.mesij-api/mesij-api.sqlite3 --project demo
```

The server binds to `127.0.0.1:7337` by default. Override with `--host` and
`--port`. Keep it on loopback unless TLS and other edge controls are provided by
a trusted reverse proxy.

Token administration:

```sh
node dist/src/cli.js token list --db ./.mesij-api/mesij-api.sqlite3 --project demo --json
node dist/src/cli.js token revoke TOKEN_ID --db ./.mesij-api/mesij-api.sqlite3 \
  --project demo --reason rotated --json
```

Revocation is append-only and idempotent. Missing, malformed, unknown, and
revoked credentials all receive the same `401` response.

## Requests

Every `/v1/*` request requires the token in this exact header name:

```http
x-message-api-token: mesij_v1.<token-id>.<secret>
```

`Authorization` is not accepted. `/healthz` is intentionally unauthenticated.

Create an event:

```sh
curl -i http://127.0.0.1:7337/v1/events \
  -H 'content-type: application/json' \
  -H "x-message-api-token: $MESIJ_API_TOKEN" \
  --data '{
    "event":"plan",
    "actor":"agent-blue",
    "session":"session-123",
    "task":"pay-142",
    "files":["src/handler.ts","migrations/0142.sql"],
    "key":"pay-142:plan",
    "message":"Planning the API change"
  }'
```

`event` accepts `plan`, `implement`, `start`, `finish`, `defer`, `post`, and
`reply`; alternatively provide a non-empty arbitrary `type`. Use exactly one of
`event` or `type`. Supported fields are:

```text
event, type, actor, session, to, reply_to, key, work, task, change,
phase, message, files, data
```

JSON is strict: the body must be one UTF-8 object, duplicate and unknown fields
are rejected, parsed objects have null prototypes, numeric lexemes must round
trip without loss through JavaScript `Number`, non-`data` fields cannot be
`null`, and both the request and resulting stored event are limited to **256
KiB**. This conservative portable ceiling stays comfortably below D1's 2 MiB
row limit.
`created_at`, IDs, and a missing idempotency key are generated by the program;
clients cannot submit `created_at`. Supplying a stable `key` is strongly
recommended. The idempotency scope is `(project, session, key)`: an identical
retry returns `200` with `inserted:false`, while changed data returns `409`.
A new event returns `201`.

`to` is stored as an **exact session string** in this MVP. It does not resolve an
actor alias, validate a reply target, or enforce private visibility.
`message.replied` requires `to`. Lifecycle validation applies whether the final
type came from `event` or explicit `type`; legacy `work.started` accepts
`phase:"implement"` but omits phase from its stored payload.

List events:

```sh
curl 'http://127.0.0.1:7337/v1/events?limit=100&type=work.planned&actor=agent-blue' \
  -H "x-message-api-token: $MESIJ_API_TOKEN"
```

Filters are `actor`, `type`, and source `session`. `limit` defaults to 100 and
is capped at 100. The first request captures a stable `through` sequence. If
`has_more` is true, pass `next_cursor` as the `cursor` query value on the next
request with the same filters. Cursors bind the filters and reject snapshots
beyond the database's current sequence. Event-list JSON is additionally capped
at approximately 4 MiB, so a page may contain fewer events than `limit` while
still returning `has_more:true`. Responses also include `next_after`; when a
snapshot is exhausted it advances to `through`.

## Cloudflare Workers and D1

1. Create a D1 database, replace both `REPLACE_WITH_D1_DATABASE_ID` and
   `REPLACE_WITH_PROJECT_ID` in `wrangler.toml`, and keep the project ID stable.
   The Worker returns `503` for a missing, empty, default, or placeholder project
   ID rather than falling back to a shared project.
2. Apply migrations locally or remotely:

```sh
npx wrangler d1 migrations apply mesij-api --local
npx wrangler d1 migrations apply mesij-api --remote
```

3. Build the CLI, then generate SQL for a program-generated token:

```sh
npm run build
node dist/src/cli.js token workers-create --project demo --label production --json
```

The JSON contains the one-time plaintext token and an `INSERT` containing only
its hash. To invoke Wrangler and apply the generated SQL directly:

```sh
node dist/src/cli.js token workers-create --project demo --label production \
  --apply --remote --database mesij-api
node dist/src/cli.js token workers-revoke TOKEN_ID --project demo \
  --reason rotated --apply --remote --database mesij-api
```

Without `--remote`, `--apply` targets Wrangler's local D1 database. `--config`
can select another Wrangler configuration. Apply schema migrations before token
SQL. Deploy with `npx wrangler deploy` after setting `MESIJ_PROJECT_ID` and the
D1 binding appropriately.

## Standalone schema and operational caveats

- `api_metadata` marks databases owned by this package. Node initialization
  refuses every non-empty unmarked database, with a specific diagnostic for a
  detected Go Mesij database. There is no supported shared-database or
  mixed-writer mode.
- The API schema and event vocabulary are internal to this standalone MVP; no
  storage compatibility with the Go CLI is promised.
- Fresh Node schema installation is one SQLite transaction: failures roll back
  all schema objects and a later initialization can resume safely.
- Node requires the database's existing parent directory to be private (`0700`),
  creates missing dedicated parents as `0700`, and secures the database file as
  `0600`. The default path is `./.mesij-api/mesij-api.sqlite3`; use a dedicated
  private directory for explicit `--db` paths.
- SQLite uses WAL and a 5-second busy timeout. D1 writes use an atomic batch.
- The Node server authenticates and routes before consuming request bodies,
  enforces the 256 KiB limit incrementally, caps headers at 16 KiB, and
  configures request, header, keep-alive, and idle timeouts.
- Tokens currently grant full read/write access to one configured project. There
  are no roles, expiry, CORS support, rate limits, token HTTP administration, or
  audit-log redaction beyond never logging request headers.
- Worker deployment and D1 creation require a Cloudflare account; tests exercise
  the shared handler and real Node `node:sqlite` adapter, not a live D1 service.

## Layout

- `src/handler.ts` — shared Fetch API router, auth, validation, and pagination
- `src/event-input.ts`, `src/strict-json.ts` — request contract and strict parser
- `src/adapters/node-sqlite.ts` — Node.js 24+ adapter and token administration
- `src/adapters/d1.ts` — Cloudflare D1 adapter
- `src/worker.ts` — Worker entry point
- `src/node-server.ts` — streaming Node HTTP adapter and transport limits
- `src/cli.ts` — database/token/server CLI and Wrangler SQL workflow
- `migrations/` — portable SQLite/D1 schema
- `test/` — shared-handler and real SQLite tests
